# 이주배경 전용 장학금 하드제약 구조화 — 설계

작성일: 2026-06-10
선행 작업: `b900c86 자격 하드제약 구조화` (군자녀·특정대학·보훈·문중)의 직접 연장선

## 목적

다문화가족·북한이탈주민 자녀 등 **이주배경 전용** 장학금이 `[자격]` 원문에만 제약을 두고
구조화 필드가 비어 있어, 해당 없는 사용자에게도 노출되는 문제를 해결한다.
마지막 커밋이 보훈/군자녀/문중을 잡았듯, 같은 메커니즘으로 이주배경을 잡는다.

## 범위 (확정)

- 데이터 조사 결과 대상은 **`data/kosaf-scholarships.json` 한 파일에 집중(약 38건)**.
  재단/국가/대학 장학금 JSON은 수작업 큐레이션이라 노이즈 없음 → 손대지 않는다.
- 신규 카테고리 빈도: 다문화 18 · 북한이탈 14 · 재외국민·귀화 **0** · 외국인유학생 2.
  → 재외국민·귀화·외국인유학생 전용 플래그는 만들지 않는다(YAGNI).

## 감지 규칙

- 트리거 정규식 `MIGRANT = 다문화 | 북한이탈 | 새터민 | 탈북`.
- **`[자격]` 구간에서만** 매칭한다(기존 스크립트와 동일). `[자격]`은 "대상 요건" 정의이므로,
  여기 키워드가 있으면 그 자체로 대상 한정 신호다. (`[자격제한]` 등 제외 구간은 보지 않는다)
- `targetGroups`가 이미 채워진 항목(보훈 분기 등에서 처리됨)은 건드리지 않는다 → 보훈 분기 뒤에 둔다.
- **다중 OR 보존(누락 방지, 보훈 분기와 동일):** 트리거되면 기존 `GROUP_MAP`을 스캔해
  `[자격]`에 언급된 사회배려 그룹 **전체**를 태깅한다.
  - 예) "부모 중 한 사람이 외국인인 가정의 자녀" → `["다문화가족"]` → 비다문화 사용자 제외(정상).
  - 예) "다문화 또는 저소득 가정" → `["다문화가족","기초생활수급자","차상위계층"]`
    → 저소득 사용자는 통과(누락 방지).

## 오탐 방지 원칙

1. `[자격]` 구간 한정 — 단순 본문 언급("다문화 우대" 등)은 트리거하지 않는다.
2. 다중 OR 항목은 그룹 전체 태깅 — 동반 대상(저소득·장애·한부모)을 잘라내지 않는다.
3. 소득 AND 조건은 `checkIncome`가 별도로 거른다 — targetGroups 과대 태깅의 부작용은 소득축에서 보정됨.
4. 기존 `targetGroups`는 덮어쓰지 않는다.

## 검증 방법

- 보정 스크립트 드라이런으로 변경 건수·샘플 확인 → `--apply`.
- 매칭 시나리오(수동):
  - 일반 사용자(이주배경 플래그 없음) → "다문화가정자녀장학생" **제외**된다.
  - `다문화가족` 플래그 선택 사용자 → 동일 항목 **노출**된다.
  - `북한이탈주민` 플래그 선택 → "북한이탈주민 특별장학생" 노출.
  - 다중 OR 항목(저소득 동반) → 저소득 사용자에게 여전히 노출(누락 없음).
- `npm run build` 통과(타입/린트).

## 비목표

- 재외국민·귀화·외국인유학생 전용 플래그 신설(데이터 0~2건).
- 신입생/편입생/학적상태 하드제약(별도 조사에서 ROI 낮음).
- 매칭 엔진·입력폼 구조 변경.
